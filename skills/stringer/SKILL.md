# 什么值得做

站在 https://stringers.io 。底下是 15 个每天采集的库(独立产品经支付平台校验的收入、App Store 115 区、Google Play、Meta / Google / TikTok 广告库、Chrome 与 Shopify 商店、GitHub、Product Hunt、HN、X 圈子、在售小生意挂牌),上面是我们每天做的整理:52 万个 App 的估算收入和投放、把做同一件事的新产品归成的赛道、每天异动的逐条调查、归纳出来的打法。调查已经做好了,你的工作是把它们和**你知道的用户情况**对起来,需要时再去库里核实。

## 手里有什么

接了 `stringer` MCP(优先):

- `list_waves` 赛道和早鸟新苗子的列表,**找方向先用它**。赛道是一件具体的事(比如「按预算和超市价格排一周晚饭」),先有一家做出量,别人再一家家跟进来做。默认按「近 3 个月新进去的人里有几家赚到钱」(月入过 $1K)排,这是现在进去还来不来得及的最直接证据。每次 10 条精简行,`offset` 翻页,`detail=true` 带分析;`kind="solo"` 是已经在赚钱、还没人跟的新产品;`q` 搜关键词或正则,字面没命中会按意思给最接近的赛道。
- `get_wave` 一条赛道的完整档案:全部成员、各自月入、逐月进场几家。`key` 给赛道的 key 或中文名;也可以给任意 App 的 key、商店链接或名字,反查它在哪条赛道、第几个进场。
- `search_apps` 在 52 万个 App 里按一句话或名字找,按相关度排。`query` 直接写它是做什么的(中英文都行),或者写 App 名字(记不准、有别字也行),不用拼关键词或正则。可叠 `rev_min`、`age_max_days`、`small_team`、`store`、`category`。结果开头会带出相关的赛道。
- `list_apps` 按条件筛一批 App,按收入 / 增长 / 新旧排序,开头给总数。适合「近半年上架、月入过 $10K 的小团队 App」这类清单。`pattern` 可以再叠一个全文正则。
- `get_app` 一个 App 的档案。`key` 可以是 `ios_123` / `play_com.x`、商店链接或名字。默认精简(数字和区间、所在赛道、各平台在不在投广告、调查稿摘要),结尾列出还能取的段;`sections="research,description"` 按需加段,`"all"` 全给。
- `query_sql` 对 App 库跑一条只读 DuckDB SQL,算分布和统计。
- `ads` 深扒一个 App 的买量素材:Meta、Google、TikTok(只有投欧洲的)、苹果 App Store 搜索广告(只有 iOS、投欧盟的)上每个平台在投 / 已停 / 查过没投 / 没查过,在投多少条、最久投了几天,投得最久和最新的广告(文案、CTA、版本数、欧盟触达、广告库原页链接)。只想知道它在不在买量,`get_app` 里已经有摘要;要逐条看素材再用它。「没查过」不等于没投;花费和 ROI 广告库不公开,别替用户估。投得久、版本多的素材通常是回本的。
- `feed` 市场动态:每天数据上突然涨起来的小产品(App、开源项目、插件、网站、独立产品收入),每条都逐个调查过为什么是这几天涨、能学什么、这波能不能持续。不带参数是最新一天;`day="2026-11-10"` 看某一天;`q` 按短词在全部日期里搜;`slug` 读一条的完整调查(定位、对手、时间线、出处、哪些没查实)。
- `plays` 打法:从这些调查里归纳的、小团队能照着做的做法。每条有分步骤、真实案例(带数字和日期)、照做却没成的反例、适合谁、什么时候不灵。不带参数是清单;`id="p04"` 读全文;`q` 搜。
- `products` 研究过的在涨产品:三千多个 App / GitHub 项目 / Chrome 插件 / 网站,每个研究过为什么跑出来、用户从哪来、竞品是谁,并给了等级。它最有用的是 `growth`:按获客做法搜实证案例。`sec`、`grade`、`q` 筛,`key` 读全文。
- `data` 查背后的原始库。

没接 MCP:只能读公开页面,不要 token。

- `https://stringers.io/index.md`:近几天的市场动态(标题、一句话原因、数字、链接)。
- `https://stringers.io/api/apps.json`、`github.json`、`chrome.json`、`web.json`:在涨的产品清单。
- `https://stringers.io/status.json`:`data_to` 是数据到哪天。落后了就跟用户说。
- 赛道、App 库、每条的完整调查、打法全文、搜索和查库都要 MCP。告诉用户去 stringers.io 登录,在「配置 agent」里拿地址。

## 等级含义

`products` 里的等级 = 现在跟进它是不是好机会(一两个人、几个月做出来并赚到钱的概率,S 最高,E 别碰;GitHub 项目按能不能拿到 star 判断)。赛道里「赚到钱」默认指月入 ≥ $1,000。

## 常用查法

1. **找方向**:先 `list_waves()` 看新进玩家还在赚到钱的赛道,`list_waves(kind="solo")` 看还没人跟的早鸟新苗子(可带 `q` 聚焦领域)。看中的用 `get_wave(key)` 读全部成员和逐月进场,再对代表产品调 `get_app(key)` 看具体做法。
2. **验想法**:`search_apps(query="一句话说它做什么")` 找同类,结果里会带出相关赛道;要按收入或上架时间排的清单用 `list_apps`,统计分布用 `query_sql`;查独立站校验实收用 `data` 查 `indie`。
3. **扒竞品**:`get_app(key="商店链接或名字")` 先看精简档案,需要调查稿全文或商店介绍再加 `sections`;要逐条看广告素材、投放时长和欧盟触达再调 `ads(app=…)`。
4. **找获客做法**:先 `plays` 找归纳好的打法,再 `products(growth="做法或渠道关键词")` 跨品类按做法搜案例,用 `products(key="…", part="growth")` 读具体起量过程。
5. **看近期异动**:`feed` 取最新一天,点单条用 `feed(slug="…")` 读完整调查。

互不依赖的查询可以同一轮并发。第一次直接查底层库先调 `data(lib, "schema")` 看表结构。
