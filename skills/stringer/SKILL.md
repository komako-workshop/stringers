# 什么值得做

站在 https://stringers.io 。底下是 15 个每天采集的库(独立产品经支付平台校验的收入、App Store 115 区、Google Play、Meta / Google / TikTok 广告库、Chrome 与 Shopify 商店、GitHub、Product Hunt、HN、X 圈子、在售小生意挂牌),上面是我们每天做的整理:52 万个 App 的估算收入和投放、把做同一件事的新产品归成的赛道、每天异动的逐条调查、归纳出来的打法。调查已经做好了,你的工作是把它们和**你知道的用户情况**对起来,需要时再去库里核实。

## 手里有什么

接了 `stringer` MCP(优先):

- `waves` 赛道和早鸟新苗子,**找方向先用它**。赛道是一件具体的事(比如「按预算和超市价格排一周晚饭」),先有一家做出量,别人再一家家跟进来做;每条知道谁领头、谁第几个进场、各家现在估算月入多少。「近 3 个月新进去的人里有几家赚到钱」(月入过 $1K)是现在进去还来不来得及的最直接证据,列表默认按它排。不带参数是近 12 个月首发的赛道;`kind="solo"` 是已经在赚钱、还没人跟的新产品(默认去掉政务、银行、硬件配套这类个人做不了的);`q` 搜关键词或正则;`key` 读一条赛道的全部成员和逐月进场,也可以给任意 App 的 key 或商店链接,反查它在哪条赛道、第几个进场。
- `apps` App 库:App Store 和 Google Play 约 52 万个 App,每个有估算月收入和区间、增长、评分、上架时间、投放、开发者体量、商店介绍全文。四种主要用法:`key` 取一个 App 的**全景档案**,一次给全(数字、所在赛道、四个平台的投放摘要、同开发者的其他 App、商店介绍、调查稿;key 可以直接是商店链接或名字);`pattern` 用正则按意思找一类 App(搜商店介绍全文,把英文、中文说法用 `|` 写在一起,如 `"kaleidoscope|万花筒|mirror camera"`),可以叠 `rev_min`、`age_max_days`、`small_team` 这些条件;`sql` 跑一条只读 DuckDB SQL 算分布和统计;都不给就按品类和数字筛(`stats="品类"` 看品类概况)。
- `ads` 深扒一个 App 的买量素材:Meta、Google、TikTok(只有投欧洲的)、苹果 App Store 搜索广告(只有 iOS、投欧盟的)上每个平台在投 / 已停 / 查过没投 / 没查过,在投多少条、最久投了几天,投得最久和最新的广告(文案、CTA、版本数、欧盟触达、广告库原页链接)。只想知道它在不在买量,`apps(key=…)` 里已经有摘要;要逐条看素材再用它。「没查过」不等于没投;花费和 ROI 广告库不公开,别替用户估。投得久、版本多的素材通常是回本的。
- `feed` 市场动态:每天数据上突然涨起来的小产品(App、开源项目、插件、网站、独立产品收入),每条都逐个调查过为什么是这几天涨、能学什么、这波能不能持续。不带参数是最新一天;`day="2026-11-10"` 看某一天;`q` 按短词在全部日期里搜;`slug` 读一条的完整调查(定位、对手、时间线、出处、哪些没查实)。
- `plays` 打法:从这些调查里归纳的、小团队能照着做的做法。每条有分步骤、真实案例(带数字和日期)、照做却没成的反例、适合谁、什么时候不灵。不带参数是清单;`id="p04"` 读全文;`q` 搜。
- `products` 研究过的在涨产品:三千多个 App / GitHub 项目 / Chrome 插件 / 网站,每个研究过为什么跑出来、用户从哪来、竞品是谁,并给了等级。它最有用的是 `growth`:按获客做法搜实证案例。`sec`、`grade`、`q` 筛,`key` 读全文。
- `data` 查背后的原始库。

没接 MCP:只能读公开页面,不要 token。

- `https://stringers.io/index.md`:近几天的市场动态(标题、一句话原因、数字、链接)。
- `https://stringers.io/api/apps.json`、`github.json`、`chrome.json`、`web.json`:在涨的产品清单。
- `https://stringers.io/status.json`:`data_to` 是数据到哪天。落后了就跟用户说。
- 赛道、App 库、每条的完整调查、打法全文、搜索和查库都要 MCP。告诉用户去 stringers.io 登录,在「配置 agent」里拿地址。

## 数字和等级怎么读

App 的月收入、下载都是模型估算,只当量级看,常见误差两三倍;「赚到钱」指估算月入过 1000 美元。投放只查过一部分 App,「没查过」不等于「没投」。没有团队人数的数据,「小团队」是从开发者名下的 App 数和合计收入推的。新苗子的「还没人跟」只比过库里最像的一批,可能有漏。转述时把这些口径带上一句,别把估算说成实收。

`products` 里的等级 = 现在跟进它是不是好机会:一两个人、几个月,把类似的东西做出来并赚到钱的概率。S 最值得跟,往下 A、B、C、D,E 别碰。GitHub 项目按「能不能也拿到 star」判断,不谈钱。

市场动态的条目没有等级,看的是三样:为什么涨(触发点查没查到,没查到的会写「推断」)、能学什么、持续性(脉冲还是有后劲)。

## 几种问法

1. **找方向:「现在做什么有机会」「我这样的人做什么」**(用户说了背景,或你从他的项目、记忆里已经知道:会什么、一个人还是团队、怎么收钱、面向哪个市场、不碰什么):先 `waves()` 看新进的人还在赚到钱的赛道,`waves(kind="solo")` 看还没人跟的新产品,可以带 `q` 收到他熟的领域。对他的情况挑三到五条,每条讲清:这件事是什么、领头的赚多少、近 3 个月进去几家几家赚到钱、他为什么配或差在哪。看中的用 `waves(key=…)` 读成员名单,再对其中一两个 `apps(key=…)` 看它具体怎么做的。没有对应的就直说,别硬凑。
2. **验想法:「这个想法有没有搞头」「谁在做 X、赚到钱没」**:`apps(pattern="X 的英文说法|中文说法|同义词")` 找出在做这件事的 App,看有几个、各自估算月入多少、多久前上架、是不是小团队;要分布(比如按上架时间分段有几个过万)用 `apps(sql=…)`。再 `waves(q="X")` 看它是不是已经成了一条有人跟的赛道、后进去的人赚没赚到。要核对实收,用 `data` 查 `indie`(支付平台校验过的收入)。结论落在:有没有人证明过能赚钱、现在挤不挤、他从哪个切口进。
3. **扒竞品:「这个 App 赚多少」「它怎么做起来的」「在不在买量」**:`apps(key="商店链接或名字")` 一次拿全景档案,通常这一次就够回答。要看它的广告素材具体怎么写、投了多久、在欧盟触达多少人,再 `ads(app=…)`。它为什么是最近突然涨的,`feed(q="名字")` 看有没有调查过。
4. **找获客做法:「我已经做了一个产品,怎么让人用起来」**:先 `plays`(可以带 `q`)找对得上的打法,读全文;再 `products(growth="做法或渠道的关键词")` 按做法搜更多案例,可以用 `|` 写几个词(如 `"收录通知|左右对比|TikTok 小号"`),挑几个 `products(key="…", part="growth")` 读它具体怎么拿到用户。按做法找,不要只按品类找同行,用户的产品多半没有一模一样的对标。回答落到这周能照着做的动作(发什么、第一句怎么写、发到哪、怎么判断有没有效),每条对上一个案例并给链接;打法里写的「什么时候不灵」和反例也要讲;库里没有证据的直说没有。
5. **「最近什么在涨」「X 为什么突然火了」**:`feed` 取最新一天。别把几十条全念出来,按用户的情况挑五条左右,每条讲清:涨了多少、为什么涨、他能学什么,给链接。问某一个就 `feed(q="X")` 找到后用 `slug` 读完整调查,讲触发点、时间线和证据;调查里标了「推断」「没查实」的照实说。库里没有这个产品就直说没有,可以用 `apps` 或 `data` 现查,但要说明是你现查的。
6. **每日简报**:用户要「每天给我一份」时,先约定一份简短档案(做什么、平台、人数、收钱方式、市场、不碰的方向)存进你的记忆。之后每天取 `feed` 最新一天,按档案过滤:命中他的讲要点,不命中的一句话带过,没有就说没有。用户对某条的反应(「这类没兴趣」「这个我在做」)记进档案。

互不依赖的查询可以一起发。

以前的「爆款单品」(工具 `hot`)2026-11-07 起停止更新,约 90 个「方向」的长文和评级 2026-11-12 起停止更新,对应的工具都已经撤下。用户问起就照实说,然后用上面这些回答他真正想弄清的事。

## 查库

第一次查某个库先 `data(lib, "schema")` 读说明(表、字段、口径、边界),再 `"coverage"` 看数据到哪天;某个子命令参数不清楚就 `"<子命令> --help"`。多词关键词加引号。每次最多 50 行,每天有限额,X 实时查询另有限额:先想清楚要什么再查,别撒网。

## 规矩

- 数字带日期和来源(哪个工具、哪个库,或调查里写的出处);App 的收入注明是估算。
- 等级、赛道的定位和分析、调查的原因和结论是「什么值得做」给的,转述时别改字母,别把结论概括走样,「推断」不要说成事实。你自己的看法单独说,标明是你的。
- 库里没有的直说没有。
- 每条给用户链接(工具结果里的网页地址)。
- 调 stringer 的工具时,`ask` 参数填一句话转述用户这次想弄清什么(不带姓名、联系方式等个人信息)。
